# Adds a processing status to submitted stablecoin payments

## What’s new

[PaymentIntents](https://docs.stripe.com/api/payment_intents.md?api-version=2025-09-30.clover) confirmed with the `crypto` payment method for [stablecoin payments](https://docs.stripe.com/payments/stablecoin-payments.md) now have a [status](https://docs.stripe.com/api/payment_intents/object.md?api-version=2025-09-30.clover#payment_intent_object-status) of `processing` when a user submits a transaction to the blockchain for processing. Users only redirect back to your integration when a payment is finalised.

## Impact

Previously, the PaymentIntent denoted success or failure by transitioning from `requires_action` to either `succeeded` or `requires_payment_method`.

With this change, when using the `crypto` payment method:

- If you [retrieve](https://docs.stripe.com/api/payment_intents/retrieve.md?api-version=2025-09-30.clover) the PaymentIntent while customers are waiting for the transaction to confirm, the `status` field now shows a value of `processing`.
- If you attempt to [cancel](https://docs.stripe.com/api/payment_intents/cancel.md?api-version=2025-09-30.clover) a confirmed PaymentIntent with the `processing` status, the request fails with error `payment_intent_invalid_cancellation_state`.

You can optionally set up your webhook endpoint to listen for the `payment_intent.processing` event to be notified when the PaymentIntent transitions to the `processing` status.

The customer isn’t redirected while the PaymentIntent has the `processing` status, so your checkout experience shouldn’t require any changes.
