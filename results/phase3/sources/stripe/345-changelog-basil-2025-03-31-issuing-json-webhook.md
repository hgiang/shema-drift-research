# HTTP Accept headers for webhooks now specify JSON during Issuing authorisations

## What’s new

Webhooks emitted for [Issuing real-time authorisations](https://docs.stripe.com/issuing/controls/real-time-authorizations.md) now specify `application/json` in the request `Accept` header. This change improves the clarity of content negotiation, because real-time authorisation webhooks require a JSON response from your integration.

## Why is this a breaking change?

Your [webhook handler](https://docs.stripe.com/webhooks.md#webhook-endpoint-def) might return an HTTP response code 406 if it doesn’t support JSON as a response format. These errors are visible in [Workbench](https://docs.stripe.com/workbench.md). If you use [Issuing real-time authorisations](https://docs.stripe.com/issuing/controls/real-time-authorizations.md), a response code other than 200 might cause your authorisations to decline.

## Impact

[Issuing real-time authorisations](https://docs.stripe.com/issuing/controls/real-time-authorizations.md) require JSON responses to `issuing_authorization.request` webhooks. Those webhooks’ `Accept` headers now specify `application/json` in order to align with that requirement.

## Upgrade

#### REST API

1. [View your current API version](https://docs.stripe.com/workbench/guides.md#view-api-versions) in Workbench.
2. If you use an SDK, upgrade to the corresponding SDK version for this API version.
   - If you don’t use an SDK, update your [API requests](https://docs.stripe.com/api-versions.md#how-versions-are-specified-in-requests) to include `Stripe-Version: 2025-03-31.basil`
3. Upgrade the API version used for [webhook endpoints](https://docs.stripe.com/webhooks/versioning.md).
4. [Test your integration](https://docs.stripe.com/testing.md) against the new version.
5. If you use Connect, [test your Connect integration](https://docs.stripe.com/connect/testing.md).

Learn more about [Stripe API upgrades](https://docs.stripe.com/upgrades.md).
