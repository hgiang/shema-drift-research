# Adds rejected status for Accounts v2 capabilities

## What’s new

Adds a rejected value to the [status](https://docs.stripe.com/api/v2/core/accounts/object.md?api-version=2026-09-30.preview#v2_core_account_object-merchant) property of capability configurations on the [Account](https://docs.stripe.com/api/v2/core/accounts/object.md?api-version=2026-09-30.preview) object in the Accounts v2 API. This status appears alongside the existing values `active`, `pending`, `restricted` and `unsupported`.

Also adds [status_details](https://docs.stripe.com/api/v2/core/accounts/object.md?api-version=2026-09-30.preview#v2_core_account_object-merchant) codes that describe the reason for rejection, including `rejected_fraud`, `rejected_incomplete_verification`, `rejected_listed`, `rejected_other`, `rejected_platform_fraud`, `rejected_platform_other`, `rejected_platform_terms_of_service` and `rejected_terms_of_service`. These codes apply to capability status across [merchant](https://docs.stripe.com/api/v2/core/accounts/object.md?api-version=2026-09-30.preview#v2_core_account_object-merchant), [recipient](https://docs.stripe.com/api/v2/core/accounts/object.md?api-version=2026-09-30.preview#v2_core_account_object-recipient) and [money_manager](https://docs.stripe.com/api/v2/core/accounts/object.md?api-version=2026-09-30.preview#v2_core_account_object-money_manager) configurations.

On API versions before `2026-09-30.preview`, the `rejected` status falls back to `restricted` and the `rejected_*` `status_details` codes fall back to `restricted_other`.

## Why is this a breaking change?

Previously, rejected accounts returned a `status` of `restricted` with a `status_details` code of `requirements_past_due`. On API version `2026-09-30.preview` and later, these accounts return a `status` of `rejected` with a specific `rejected_*` code instead. If your integration checks for `restricted` status to identify rejected accounts, you must update your code to also handle the `rejected` status and the associated detail codes.

## Impact

If your integration reads capability `status` or `status_details` values from Accounts v2 [Account](https://docs.stripe.com/api/v2/core/accounts/object.md?api-version=2026-09-30.preview) objects, you can receive the `rejected` status and `rejected_*` detail codes after upgrading to API version `2026-09-30.preview`. Update any code that handles these properties to account for these values. This also affects the `v2.core.account[configuration.*.capability_status_updated]` and `v2.core.account[requirements].updated` events, which now emit the `rejected` status for rejected accounts.
