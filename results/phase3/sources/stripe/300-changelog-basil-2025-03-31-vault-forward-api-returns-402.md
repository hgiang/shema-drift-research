# Updates the Vault and Forward API to return a 402 status code for upstream request timeouts

## What’s new

The [Vault and Forward](https://docs.stripe.com/payments/vault-and-forward.md) API now returns a `402` error instead of `502` and `504` errors for specific scenarios.

## Why is this a breaking change?

Some users might expect either `502` or `504` statuses for upstream errors. Update your code to expect `402` statuses as well.

## Impact

Previously, the Vault and Forward API returned a `502` or `504` error for any errors with the upstream destination endpoint, regardless of connection status. Now, you receive a `402` error if a request times out before Stripe establishes a connection with the upstream, allowing for safe retries. Stripe continues returning `502` or `504` errors for all other upstream errors.

## Upgrade

#### REST API

1. [View your current API version](https://docs.stripe.com/workbench/guides.md#view-api-versions) in Workbench.
2. If you use an SDK, upgrade to the corresponding SDK version for this API version.
   - If you don’t use an SDK, update your [API requests](https://docs.stripe.com/api-versions.md#how-versions-are-specified-in-requests) to include `Stripe-Version: 2025-03-31.basil`
3. Upgrade the API version used for [webhook endpoints](https://docs.stripe.com/webhooks/versioning.md).
4. [Test your integration](https://docs.stripe.com/testing.md) against the new version.
5. If you use Connect, [test your Connect integration](https://docs.stripe.com/connect/testing.md).

Learn more about [Stripe API upgrades](https://docs.stripe.com/upgrades.md).
